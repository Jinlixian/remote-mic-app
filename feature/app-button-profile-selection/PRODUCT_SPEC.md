# 按 APP 选择键位方案产品规范

> 状态：候选实现已完成（2026-11-23），公开构建与定向自动化通过；真实遥控器、私有方案组件与第三方 APP 前台流程待验收。测试手册：[`Testing/ApplicationButtonProfiles.md`](../../Testing/ApplicationButtonProfiles.md)。
> 适用：macOS 设置窗口「聚焦与翻页」中点「设置这个 APP 的按键」进入的 APP 按键二级页。
> 前置能力：[按 APP 自定义普通按键动作](../application-button-overrides/PRODUCT_SPEC.md)、[按键页作用域拆分](../mapping-scope-separation/PRODUCT_SPEC.md)、[键位方案作用域编辑](../button-profile-scope/README.md)。

## 用户目标

1. 全局按键配置对应「默认方案」。
2. 在某个 APP 里配置按键时，可以从方案列表里选一套已有方案；选中即生效。
3. 在 APP 页继续改按键，改完保存就生成一套**新方案**（带名字），进入方案列表；原方案不变。
4. 下次配置其它 APP 时，可以直接从列表里选刚生成的方案。

方案是列表里的可复用配置；APP 只负责**选择**或**另存**，不修改别人正在用的方案。

## 已确认的取舍

| 问题 | 决定 |
| --- | --- |
| 设备作用域 | APP 只存一个方案引用，不按遥控器分别存。方案对当前遥控器不适用时，APP 页明确标注「不适用」且不可选；运行期回退默认方案并提示，不静默套用别的动作。 |
| 逐项覆盖 | 保留既有「按 APP 单独设置按键」能力，优先级高于所选方案。未逐项覆盖的手势使用所选方案，未在方案里覆盖的手势继承基础映射。 |
| 编辑语义 | APP 页只做「选择方案 / 编辑按键」。选已有方案 = 直接使用；在该方案基础上继续改并保存 = 复制生成**新方案**，原方案不被修改。不提供「更新原方案」入口。 |
| 私有仓 | 不为本功能额外要求私有仓改接口。运行时通过公开适配层已有的方案读取接口取值，再走宿主既有动作执行链；私有方案组件不可用时整体降级并明确提示。 |

## 术语

| 术语 | 含义 |
| --- | --- |
| 默认方案 | 不指定方案。按键按全局规则解析：当前全局生效方案 → 基础映射；APP 逐项覆盖仍最优先。 |
| 方案（键位方案） | 私有按键方案组件里的 `ButtonMappingProfile`，覆盖 10 个普通按键的单击/双击/长按；未覆盖手势继承基础映射。 |
| APP 指定方案 | `CustomApplicationProfile.mappingProfileID` 非空：该 APP 前台时使用这套方案，替代全局当前生效方案。 |
| 另存为新方案 | 把当前 APP 的最终按键效果（所选方案 + 逐项覆盖）冻结成一套方案，并让该 APP 指向它；若已有方案的操作完全一致，直接复用该方案，不新建重复项。 |

## 数据模型

```text
CustomApplicationProfile
  mappingProfileID: UUID?                       // 新增；nil = 默认方案
  buttonBindings: [ApplicationButtonBinding]?   // 既有逐项覆盖，优先级最高
```

- `nil`、缺省、无法解析都表示默认方案。
- APP 级一个引用，不按设备分开；不新增 UserDefaults 顶层键，仍随 `customApplicationProfiles` 数组保存。

## 运行期解析

### 优先级（高到低）

1. APP 逐项覆盖 `buttonBindings`。
2. APP 指定方案 `mappingProfileID`：命中的手势执行方案动作；方案未覆盖的手势继承基础映射。
3. 全局当前生效方案（`activeMappingProfileID(device:)`）。
4. 基础映射。

显式「不执行」在任意一层都是有效值，不穿透到下一层。

### 适用性

APP 指定方案在下面全部成立时才参与解析：

- 方案存在于当前遥控器可用的方案列表（`profiles(for: device)`）；
- 方案可读、已解锁；
- 能够读到该手势的方案绑定。

任一不成立：该 APP 回退默认方案；APP 按键设置页显示可恢复原因（方案已删除 / 不适用于当前遥控器 / 未解锁 / 组件不可用）。不得改执行成另一套方案的动作。

### 执行方式

- 宿主通过公开适配层读取方案绑定（`displayProfileBinding`）拿到与编辑器一致的动作模型，再交给现有动作执行链（内部动作、快捷键、打开 APP、宏）。
- 方案手势未覆盖时返回「继承」，宿主按全局规则解析。
- 宏、组合动作仍由现有宏组件执行，不在公开层另写一套解析。
- 原生透传、双击/长按 preflight、手势快照必须看到所选方案与逐项覆盖，避免误判为无次级手势。

### 前台切换

沿用现有清理规则：切换时取消未完成普通手势、按住与连发；旧 APP 的逐项覆盖与指定方案都不得混入新 APP。

## UI

### APP 按键设置页「按键方案」卡片

位置：点「设置这个 APP 的按键」进入的二级页顶部，不单独摆在 APP 详情里，也不与「按 APP 设置按键」并列为两张卡片。

- 默认方案：方案选择框显示「默认方案」，下方说明「与全局按键页当前生效的方案一致」；右侧「另存为新方案」。
- 已指定：选择框直接显示已选的方案名，下方显示「当前遥控器可用 / 不适用」；右侧「另存为新方案」。
- 方案不可用（删除 / 不适用 / 未解锁 / 组件缺失）：选择框显示「不可用方案」，下方橙色标注具体原因；用户可在同一选择框改回默认；逐项覆盖保留。

### 方案选择框

- 使用页面内的下拉选择框，不用按钮再打开 Sheet。
- 选择框直接显示当前方案：首次为「默认方案」，已设置过则显示之前选中的方案；方案失效时显示「不可用方案」。
- 选项顺序：默认方案 → 当前遥控器可用的方案列表；未解锁或不适用的方案不进入可选项。
- 选中即写入 APP 档案并立即刷新；写入失败保持原值并提示。

### APP 按键二级页

页头只保留返回与页面标题；当前方案与适用状态统一放在顶部「按键方案」卡片，避免重复。

- 默认方案：保持现有逐项覆盖编辑；每项继承分两段说明「全局当前生效方案 / 基础映射」。提供「另存为新方案…」。
- 已指定方案：
  - 每项未逐项覆盖时显示所选方案的动作；方案未覆盖的手势显示「继承基础映射」。
  - 编辑按键写入该 APP 的逐项覆盖（沿用即时保存），所选方案本身不被修改。
  - 「另存为新方案…」把「所选方案 + 逐项覆盖」的最终效果创建成新方案，APP 改指向新方案，并清空逐项覆盖。
  - 保存前按「按键 × 手势 → 操作」比较现有方案；操作完全一致时直接复用现有方案，不新建重复方案。比较不包含方案名、方案 ID、APP 档案名、绑定顺序、快捷键展示文字、创建时间或设备身份。
- 命名对话框：默认「<APP 名> 方案」；非空、去首尾空白；重名提示但允许改名；失败保留现状并提示。
- 另存成功后，方案列表立即出现新方案；若命中已有方案则直接指向已有方案。其它 APP 可立即选择。
- 中文最终字号 ≥12pt；沿用现有卡片栅格，不新增长下拉。

## 兼容与边界

1. 旧配置缺省 `mappingProfileID` → 默认方案，不迁移、不改写现有绑定。
2. 配置导出/导入仍用 `formatVersion = 2`；方案 ID 是本机标识，**不跨机保留**：导出时置空或省略，导入时清空并记录清洗数量。
3. Portable transfer 不扩展对象类型；替换 APP 档案时保留本机逐项覆盖，`mappingProfileID` 一律清空。
4. 删除方案：所有引用它的 APP 回退默认方案，逐项覆盖保留，详情显示「方案已删除，已回到默认方案」；不删除 APP。
5. 删除 APP：只删引用与逐项覆盖，不删方案。
6. 选择「不适用」的方案被拒绝，不写入；若方案在写入后变得不适用（换遥控器/被删），运行期回退默认并提示。
7. 私有方案组件不可用（`mappingProfiles` 为空）：卡片显示「需要按键方案组件」并禁用选择；运行期仍按现有全局方案执行，不新增其它行为。

## 日志与隐私

- 记录：选择方案 / 改回默认 / 另存为新方案 / 运行期命中与回退 / 导入清洗 / 方案删除后的回退。
- 字段只用稳定枚举：`scope=app|global`、`mode=default|assigned`、`resolution=assigned|fallback_missing|fallback_inapplicable|fallback_locked|fallback_component|fallback_profile_deleted`、`result=success|failed|cancelled`、`count`。
- 不记录 APP 名称、Bundle Identifier、路径、方案名、方案 ID、设备身份、快捷键正文。
- 一次操作只产生一个最终结果；UI 刷新、入队、解码都不算成功。

## 验收

1. APP A 选方案 X、APP B 默认：前台切换后第一次按键分别命中，切回不残留。
2. 方案 X 未覆盖的手势按基础映射；逐项覆盖存在时优先于方案。
3. 在 APP A 里基于方案 X 改按键并另存：方案列表出现新方案 Y，APP A 指向 Y，方案 X 内容不变。
4. 其它 APP 立即能选到 Y；选 Y 后不适用当前遥控器时明确标注且不可选，运行期回退默认。
5. 删除方案 X 后引用它的 APP 回退默认，逐项覆盖保留，可恢复。
6. 未解锁方案不可选、不可读；组件缺失时入口禁用并说明，运行期行为不变。
7. 导入配置不携带方案 ID；导入后 APP 回到默认方案并有一次性说明。
8. 连续快速按、断连、权限撤销、自定义映射关闭、前台切换后无旧 APP 动作或旧方案残留。
9. 中英文、浅色/深色、生产默认与最小窗口下，卡片、选择框、命名弹窗与警告不裁切、不横向滚动。
10. 真实遥控器、iPhone/网页/Watch 与目标第三方 APP 前台流程分别记录自动化、真实窗口、代理实测和用户实测边界；未完成只能标待验证。

## 明确不做

1. 不按遥控器设备分别保存方案引用。
2. 不提供「更新原方案」或原地修改共用方案；编辑一律另存新方案。
3. 不给语音键增加方案级动作。
4. 不新增侧边栏一级页面、独立窗口或全局单例导航。
5. 不改变方案页的创建、复制、导入导出、市场与会员流程。
6. 不在公开层重写宏/组合动作执行。

## 落地顺序

1. 数据模型与持久化：`mappingProfileID`、导入清洗、删除回退。
2. 解析收口：优先级与适用性判定；preflight、快照、执行三处同源。
3. APP 按键设置页顶部方案卡片 + 选择框。
4. APP 按键页方案展示 + 另存为新方案（命名、列表刷新、清空逐项覆盖）。
5. 降级、日志、自动化与真机验收、截图证据。
