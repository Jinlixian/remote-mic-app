# 按 APP 选择键位方案产品规范

> 状态：设计草案（2026-11-23），待评审；未进入实现。
> 适用：macOS 设置窗口「聚焦与翻页」的 APP 详情与 APP 按键二级页。
> 前置能力：[按 APP 自定义普通按键动作](../application-button-overrides/PRODUCT_SPEC.md)、[按键页作用域拆分](../mapping-scope-separation/PRODUCT_SPEC.md)、[键位方案作用域编辑](../button-profile-scope/README.md)。

## 用户问题与目标

现在同一按键在某个 APP 前台时只能靠「逐项覆盖」改一两个键，没法把整套 10 个普通按键的搭配带过去。用户希望：

1. 全局用一套配置，名字叫「默认方案」。
2. 在 APP A 里给按键时可以选一套方案：用默认方案，或选一套已有方案。
3. 也可以在 APP 里直接改按键，改完保存成一套新方案并起名，进入方案列表。
4. 下次配置另一个 APP 时，能直接选刚保存的方案；选中后仍可继续改，改完可以更新原方案，也可以另存为新方案。

目标是把「方案」变成可复用、可命名的整体配置；APP 只负责**选择**方案，方案内容仍是同一份数据。

## 术语

| 术语 | 含义 |
| --- | --- |
| 默认方案 | 不指定任何方案。按键按全局规则解析：当前生效方案 → 基础映射；该 APP 的逐项覆盖仍然最优先。界面文案统一为「默认方案」。 |
| 方案（键位方案） | 私有按键方案组件里的 `ButtonMappingProfile`，覆盖 10 个普通按键的单击/双击/长按；未覆盖的手势继承基础映射。 |
| APP 指定方案 | `CustomApplicationProfile.mappingProfileID` 非空：该 APP 在前台时固定使用这套方案，替代「当前生效方案」。 |
| 生效方案 | 某个 APP 前台、一个按键事件最终拿到的方案：APP 指定方案（若可用）或当前全局生效方案。 |

## 数据模型

### APP 档案新增字段

```text
CustomApplicationProfile
  mappingProfileID: UUID?   // 新增，可选；nil = 默认方案
  buttonBindings: [ApplicationButtonBinding]?  // 既有，逐项覆盖；优先级高于方案
```

- `nil`、缺省、无法解析都表示「默认方案」。
- 该字段是 APP 级，不按遥控器设备分别保存。
- 不新增 UserDefaults 顶层键；仍随 `customApplicationProfiles` 数组保存。

### 方案草稿（仅编辑期，不落盘）

```text
ButtonProfileDraft
  originProfileID: UUID?            // nil = 全新方案
  name: String
  bindings: [button, trigger, ConfiguredButtonAction]
  holdModes: [button: RemoteButtonHoldMode]
  seededFromAppID: UUID?            // 从哪个 APP 的当前生效动作起步
```

草稿只在内存中存在；保存时要么写入原方案，要么创建新方案，要么放弃。

## 运行期解析

### 优先级（从高到低）

1. 该 APP 的逐项覆盖 `buttonBindings`（既有能力，不因方案变化而失效）。
2. 该 APP 指定的方案 `mappingProfileID`：命中该手势则执行方案动作，未覆盖的手势**继承基础映射**，不继承全局当前生效方案。
3. 当前全局生效方案（`activeMappingProfileID(device:)`）。
4. 基础映射。

显式「不执行」在任意一层都是有效值，不得穿透到下一层。

### 可用性判定

APP 指定方案只有在下面全部成立时才参与解析：

- 方案存在于当前遥控器可用的方案列表（`profiles(for: device)`）；
- 方案处于已解锁、可读取状态；
- 私有按键方案组件具备按指定方案执行的能力（见「私有组件接口需求」）。

任一条件不成立时回退到「当前全局生效方案」，并在 APP 详情与按键页显示可恢复的提示，不静默改成别的动作。

### 前台切换

沿用现有清理规则：前台切换时取消未完成普通手势、按住与连发；旧 APP 的逐项覆盖和指定方案都不得混入新 APP 的解析结果。

## UI 与交互

### APP 详情页新增「按键方案」卡片

位置：现有「按 APP 设置按键」卡片之后，同一列。

- **默认方案**：显示「默认方案」+ 说明「与全局按键页当前生效的方案一致」；右侧按钮「选择方案」。
- **已指定方案**：显示方案名、被多少个 APP 共用；按钮「编辑方案」「改回默认方案」「选择方案」。
- 指定的方案不可用（被删、未解锁、不适用当前遥控器）时，卡片显示警告和原因，并提供「重新选择」。

### 选择方案面板

- 使用 Sheet 或页面内浮层，不使用下拉列表。
- 分组顺序：
  1. 「默认方案」单项卡片（单选语义，附说明）。
  2. 「我的方案」：每套方案一张卡片，显示名称、是否被其它 APP 使用、锁定状态；单选。
  3. 「新建方案…」入口固定在列表末尾。
- 未解锁方案不得显示内容、不得可选；只显示会员引导。
- 选中已有方案后立即写入 APP 档案；选「新建方案」进入草稿编辑。
- 取消不改数据。选中失败必须提示并保持原值。

### APP 按键二级页

**默认方案模式**：保持现有逐项覆盖界面；页头新增「选择方案」入口和当前方案显示「默认方案」。

**指定方案模式**：

- 页面进入时把该方案内容读入草稿；按钮卡片显示方案值，未覆盖的手势标「继承基础映射」。
- 页面顶部固定显示方案名和「同被 N 个 APP 使用」；N > 1 时显示「修改会影响这些 APP」。
- 页头右侧「保存」「取消」；离开有未保存修改时必须二次确认。
- 「另存为新方案」始终可用。
- 保存时：
  - 草稿来源是全新方案：弹出命名对话框，创建方案，创建成功后把 APP 指向新方案；失败则保留草稿并提示，不写入半成品。
  - 草稿来源是已有方案：弹出三选一「更新“方案 A”（影响 N 个 APP）」「另存为新方案」「取消」；更新必须整笔成功或整笔回滚。
- 命名规则：默认「<APP 名> 方案」；必须非空、去首尾空白、同设备下重名需用户确认；不得只用空白字符。

### 草案的起点

- 从已有方案进入：草稿等于该方案当前内容。
- 从「新建方案」进入：草稿以该 APP 当前实际生效动作为起点（含逐项覆盖），用户改完直接保存即可得到与原效果一致的新方案。
- 不复制其它 APP 的逐项覆盖，也不复制方案的失效引用提示状态。

### 文案与布局

- 中文界面最终字号不得小于 12pt；沿用现有卡片栅格，不新增长下拉。
- 新增中英文 key 统一前缀 `application_profile.`；中文与英文必须同批进入两份本地化表并通过 `verify-localizations.sh`。
- 方案名属于用户内容，在截图中必须使用脱敏名称。

## 私有组件接口需求

当前公开适配层只能按「设备档案 + 当前活动方案」执行：`hasActiveBinding(profileID:button:trigger:)`、`executeBoundAction(profileID:button:trigger:...)` 的 `profileID` 是遥控器设备档案，不是方案。要按 APP 指定方案执行，需要私有 `SayAllButtonProfiles` 增加以下之一：

1. 显式方案执行：`executeBoundAction(mappingProfileID:deviceProfileID:button:trigger:performers...)` 与对应的 `hasBinding` 查询；或
2. 临时方案覆盖：按一次按键事件注入方案 ID，事件结束立即失效。

要求：

- 缺接口时公开层必须能力降级：隐藏「选择方案」入口或置灰并说明「需要更新按键方案组件」，运行时继续按当前生效方案执行。
- 不得由宿主自行拼装方案内容的执行链来绕开私有组件：宏、组合动作和快捷键解析必须与方案页一致。
- 会员门禁必须沿用组件内的可读/可编辑判定，不得通过公开层旁路读取未解锁方案。

## 数据与兼容

1. `mappingProfileID` 是可选字段；旧配置缺省时全部 APP 使用默认方案，升级不迁移、不改写现有绑定。
2. 配置导出/导入仍使用 `formatVersion = 2`。方案 ID 是本机私有组件的标识，**不导出、不参与跨机导入**；导入时必须清空该字段并记录清洗数量，避免悬空引用。
3. Portable transfer 不扩展新对象类型；替换 APP 档案时保留本机字段，但 `mappingProfileID` 一律清空。
4. 删除方案：所有引用该方案的 APP 立即回退默认方案，保留逐项覆盖；详情显示「方案已删除，已回到默认方案」。不得删除 APP 档案。
5. 删除 APP 档案：只删除该 APP 的引用与逐项覆盖，不删除方案本身。
6. 方案改名、复制、失效引用清理沿用现有方案页规则，不新增第二套生命周期。

## 日志与隐私

- 必须记录：选择/改回默认、草稿保存（新建/更新/另存）、解析命中与各类回退、导入清洗、方案删除后的引用回退。
- 字段只允许稳定枚举：`scope=app|global`、`mode=default|assigned`、`resolution=assigned|fallback_missing|fallback_locked|fallback_unsupported|fallback_profile_deleted`、`result=success|failed|cancelled`、`count`。
- 不得记录 APP 名称、Bundle Identifier、路径、方案名、方案 ID、设备身份或快捷键正文。
- 一次用户操作只产生一个最终结果；入队、解码和 UI 已刷新都不算成功。

## 验收

1. APP A 指定方案 X、APP B 使用默认方案：前台切换后第一次按键即分别命中，切回不残留。
2. 方案 X 未覆盖的手势按基础映射执行，不继承全局当前生效方案。
3. 从 APP 页新建方案并命名：方案出现在选择列表，其它 APP 可立即选择；APP A 保存后立即指向新方案。
4. 已有方案被多个 APP 使用时，在 APP 页修改并「更新」会影响全部引用 APP；「另存为新方案」只影响当前 APP。
5. 未解锁方案不可选、不可读；组件缺少显式方案执行接口时入口降级且运行期不改变现有方案行为。
6. 删除方案、删除 APP、方案不可用于当前遥控器、导入清洗四类边界都回退默认方案并可恢复，不出现死键。
7. 逐项覆盖与指定方案同时存在时，逐项覆盖优先；清除逐项覆盖后方案立即恢复。
8. 配置导出/导入不携带跨机方案 ID；导入后 APP 回到默认方案并给出一次性说明。
9. 连续快速按、断连、权限撤销、自定义映射关闭、前台切换后无旧 APP 动作或旧方案残留。
10. 中英文、浅色/深色、生产默认与最小窗口下，方案卡片、草稿页、命名弹窗和警告不裁切、不横向滚动，中文最终字号 ≥12pt。
11. 真实遥控器、iPhone/网页/Watch 与目标第三方 APP 前台流程分别记录自动化、真实窗口、代理实测和用户实测边界；未完成时只能标记为待验证。

## 明确不做

1. 不做「同一 APP 在不同遥控器上使用不同方案」；本版 APP 级只存一个方案引用，设备不适用时回退。
2. 不给语音键增加方案级动作，不改变语音键手势限制。
3. 不把方案内容另存成第二份可写副本；草稿只存在于编辑期，保存后仍回到唯一一份方案。
4. 不新增侧边栏一级页面、独立窗口或全局单例导航状态；入口仍从 APP 详情进入。
5. 不改变方案页的创建、复制、导入导出、市场与会员流程。
6. 不在公开层自行执行宏或组合动作。

## 待评审的取舍

1. **设备作用域**：方案是否随遥控器设备分开？本版建议 APP 级单引用 + 不适用时回退；若要按设备分别保存，需要把字段升级为 `[deviceID: UUID]`。
2. **逐项覆盖与指定方案共存**：本版保留逐项覆盖且优先级最高；若评审认为会增加理解成本，可改为「指定方案时清除逐项覆盖」。
3. **共用方案的修改入口**：本版允许从 APP 页发起草稿并选择「更新/另存」；若坚持「一个配置项只能有一个权威编辑位置」，则 APP 页只保留只读预览与「去方案页编辑」跳转。
4. **默认方案文案**：私有「默认」方案本身代表基础映射；当全局存在生效方案时，APP 选择「默认方案」显示的是全局生效结果，需在说明文案中明确，避免误解为「只用基础映射」。

## 落地顺序（建议）

1. 私有仓补齐显式方案执行接口与能力查询。
2. 公开仓数据模型与解析收口：`AppSettings.configuredAction` 增加 APP 指定方案分支；解析结果单一出口。
3. APP 详情卡片 + 选择面板 + 草稿页；先只支持「选择/改回默认」。
4. 草稿保存（新建/更新/另存）、共用影响提示与命名校验。
5. 导入清洗、删除方案回退、日志与降级。
6. 自动化 + 真机验收 + 截图证据。
