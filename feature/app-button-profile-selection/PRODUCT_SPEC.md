# 按 APP 选择键位方案产品规范

> 状态：方案归属模型已改为「修改者拥有」，实现与验收进行中（2026-11-23）。旧 APP 配置只做兼容读取和冻结保留，不改写用户当时记录的内容；真实遥控器、完整集成组件与第三方 APP 前台流程待验收。
> 适用：macOS 设置窗口「聚焦与翻页」中点「设置这个 APP 的按键」进入的 APP 按键二级页。
> 前置能力：[按 APP 自定义普通按键动作](../application-button-overrides/PRODUCT_SPEC.md)、[按键页作用域拆分](../mapping-scope-separation/PRODUCT_SPEC.md)、[键位方案作用域编辑](../button-profile-scope/README.md)。

## 用户目标

1. 全局按键配置对应「默认方案」。
2. 在某个 APP 里配置按键时，可以从方案列表里选一套已有方案；选中即生效。
3. 在 APP 页修改按键时，修改结果直接成为**这个 APP 自己的方案**，不需要用户先点「另存」。
4. 另一个 APP 选择这套方案且没有修改时，直接跟随它；一旦修改，就形成修改者自己的方案。
5. 方案列表只展示真实存在的独立方案，不展示「母方案 / 子方案 / 派生方案」这类关系。

## 方案归属唯一规则

**方案的归属跟着最后一次修改它的 APP 走；没有修改时，归属保持不变。**

| 场景 | 结果 |
| --- | --- |
| A 选择 B 的方案，A 没有修改 | A 当前使用的就是 B 的方案。A 的按键随 B 后续修改而变化。 |
| A 选择 B 的方案，A 修改了一个按键 | 在 A 当前看到的最终效果上形成 A 自己的方案；B 的方案完全不变。A 改为使用 A 的方案。 |
| C 选择 A 的方案，C 没有修改 | C 当前使用的就是 A 的方案。A 后续修改，C 跟着变。 |
| C 选择 A 的方案，C 修改了一个按键 | 在 C 当前看到的最终效果上形成 C 自己的方案；A 的方案完全不变。C 改为使用 C 的方案。 |
| A 改回默认方案 | A 不再引用任何方案，使用全局规则；A 自己的方案保留在列表中，可被其它 APP 选择。 |

### 没有子母方案

- 方案只有「当前归谁」和「当前内容」，没有来源、父方案、子方案、派生链或「基于某方案」字段。
- B 的方案最初可能来自 C，但 B 修改完成后，它就是 B 的独立方案，和 C 的方案没有任何关系。
- 即使两套方案里有些按键恰好相同，也只是值相同，不是从属关系。
- 之后 C 改 C 的方案，B 不受影响；B 改 B 的方案，C 也不受影响。
- 只有两个 APP 还同时引用**同一个方案对象**、且都没有修改时，才会共享后续变化。

### 方案名称与归属

- 自动形成的方案默认命名为「<APP 名> 方案」，归属该 APP。
- 归属变化只发生在「这个 APP 修改了按键」这一动作上，不因为创建历史、导入历史或曾经引用过而改变。
- 不再把「最初创建者」当作永久归属；用户看到的是「谁现在拥有它」。
- 一套方案同一时间只有一个归属 APP；可以被多个 APP 引用，但引用不等于拥有。

## 已确认的取舍

| 问题 | 决定 |
| --- | --- |
| 设备作用域 | APP 只存一个方案引用，不按遥控器分别存。方案对当前遥控器不适用时，APP 页明确标注「不适用」且不可选；运行期回退默认方案并提示，不静默套用别的动作。 |
| APP 逐项覆盖 | 只保留菜单键与 TV 键的 APP 逐项覆盖。10 个方案作用域按键不再新增逐项覆盖；旧数据在迁移时冻结进方案。 |
| 编辑语义 | 修改即写入修改者自己的方案：已是 owner 时原地更新自己的方案；不是 owner 时先复制当前最终效果，再在副本上修改。原方案不被修改。 |
| 另存入口 | 「另存为新方案」不再承担归属转移；正常修改已经自动形成自己的方案。保留与否只影响显式复制，不影响归属规则。 |
| 私有仓 | 不为本功能额外要求私有仓改接口。私有组件可用时通过公开适配层读写；不可用时由宿主侧方案存储承接 APP 页的选择、归属和旧配置物化，全局方案页仍保持原有降级。 |

## 术语

| 术语 | 含义 |
| --- | --- |
| 默认方案 | 不指定方案。按键按全局规则解析：当前全局生效方案 → 基础映射；APP 菜单键/TV 键覆盖仍最优先。 |
| 方案（键位方案） | 私有组件的 `ButtonMappingProfile` 或宿主侧 `HostApplicationScheme`，覆盖 10 个普通按键的单击/双击/长按；未覆盖手势继承基础映射。菜单键与 TV 键不进入方案。 |
| 方案归属 | 当前拥有这套方案的 APP 档案。归属随最后一次修改者变化。 |
| APP 指定方案 | `CustomApplicationProfile.mappingProfileID` 非空：该 APP 前台时使用这套方案，替代全局当前生效方案。 |
| 修改 | 用户在 APP 按键页对方案作用域按钮的单击/双击/长按写入或清除动作。选择另一套方案不算修改，只切换引用。 |

## 数据模型

```text
CustomApplicationProfile
  mappingProfileID: UUID?                       // 当前引用；nil = 默认方案
  buttonBindings: [ApplicationButtonBinding]?   // 菜单键/TV 键覆盖；旧方案作用域覆盖仅作兼容读取

applicationSchemeOwners: [String: String]        // scheme ID → 当前归属 APP 档案 ID
```

- `mappingProfileID` 只表示「当前使用哪套方案」，不表示拥有。
- `applicationSchemeOwners` 是本机归属台账，宿主方案与私有方案共用；缺省表示归属未知。
- 归属未知的旧方案不会被强行改归属；第一次被某个 APP 修改时，形成修改者自己的新方案，旧方案保持原样。
- APP 级一个引用，不按设备分开；不新增方案对象类型，旧配置导出格式保持兼容。

## 运行期解析

### 优先级（高到低）

1. APP 菜单键/TV 键逐项覆盖 `buttonBindings`。
2. APP 指定方案 `mappingProfileID`：命中的手势执行方案动作；方案未覆盖的手势继承基础映射。
3. 全局当前生效方案（`activeMappingProfileID(device:)`）。
4. 基础映射。

显式「不执行」在任意一层都是有效值，不穿透到下一层。

### 适用性

APP 指定方案在下面全部成立时才参与解析：

- 方案存在于当前遥控器可用的方案列表（`profiles(for: device)`）；
- 方案可读、已解锁；
- 能够读到该手势的方案绑定。

任一不成立：该 APP 回退默认方案；APP 按键设置页显示可恢复原因（方案已删除 / 不适用于当前遥控器 / 未解锁 / 组件不可用）。不得改执行成另一套方案的动作。

### 执行方式

- 宿主通过公开适配层读取方案绑定（`displayProfileBinding`）拿到与编辑器一致的动作模型，再交给现有动作执行链（内部动作、快捷键、打开 APP、宏）。
- 方案手势未覆盖时返回「继承」，宿主按全局规则解析。
- 宏、组合动作仍由现有宏组件执行，不在公开层另写一套解析。
- 原生透传、双击/长按 preflight、手势快照必须看到所选方案与菜单键/TV 键覆盖，避免误判为无次级手势。

### 前台切换

沿用现有清理规则：切换时取消未完成普通手势、按住与连发；旧 APP 的覆盖与指定方案都不得混入新 APP。

## 编辑写入规则

### 用户修改方案作用域按键

1. 解析这个 APP 当前最终效果：所选方案 + 该 APP 的旧逐项覆盖 + 全局回退。
2. 找到这个 APP 自己拥有的方案；没有则新建「<APP 名> 方案」并登记归属。
3. 如果这个 APP 已经拥有当前引用的方案：只更新该方案里的这个按键/手势。
4. 如果这个 APP 没有拥有当前引用的方案：把第 1 步的最终效果完整写入自己的方案，再应用本次修改。
5. 让这个 APP 指向自己的方案，清空该 APP 的方案作用域旧逐项覆盖；菜单键/TV 键覆盖保留。
6. 当前引用的原方案不被修改；其它引用原方案的 APP 不受影响。

### 用户清除某个按键动作

- 如果这个 APP 拥有当前方案：从自己的方案中移除该手势，回到方案内继承。
- 如果这个 APP 不拥有当前方案：只清除该 APP 残留的旧逐项覆盖，不改动别人的方案，也不因此强行复制方案。

### 用户选择另一套方案

- 只切换 `mappingProfileID`，不复制、不改名、不改归属。
- 这个 APP 原先拥有的方案继续保留，可被其它 APP 选择。
- 如果这个 APP 已有方案作用域旧逐项覆盖，选择后仍按兼容优先级生效；下一次修改任意方案作用域按键时，统一冻结进自己的方案并清空。

### 用户修改菜单键或 TV 键

- 继续写 APP 逐项覆盖，不进入方案，不改变方案归属。

## UI

### APP 按键设置页「按键方案」卡片

位置：点「设置这个 APP 的按键」进入的二级页顶部，不单独摆在 APP 详情里，也不与「按 APP 设置按键」并列为两张卡片。

- 默认方案：方案选择框显示「默认方案」，下方说明「与全局按键页当前生效的方案一致」。
- 已指定：选择框直接显示已选的方案名，下方显示「当前遥控器可用 / 不适用」，并显示当前归属 APP。
- 方案不可用（删除 / 不适用 / 未解锁 / 组件缺失）：选择框显示「不可用方案」，下方橙色标注具体原因；用户可在同一选择框改回默认。
- 归属显示只表达当前拥有者，不显示「来自某方案」「父/子方案」或创建历史。

### 方案选择框

- 使用页面内的下拉选择框，不用按钮再打开 Sheet。
- 选择框直接显示当前方案：首次为「默认方案」，已设置过则显示之前选中的方案；方案失效时显示「不可用方案」。
- 选项顺序：默认方案 → 当前遥控器可用的方案列表；未解锁或不适用的方案不进入可选项。
- 选中即写入 APP 档案并立即刷新；写入失败保持原值并提示。

### APP 按键二级页

页头只保留返回与页面标题；当前方案与适用状态统一放在顶部「按键方案」卡片，避免重复。

- 默认方案：每项继承分两段说明「全局当前生效方案 / 基础映射」。
- 已指定方案：每项未覆盖时显示所选方案的动作；方案未覆盖的手势显示「继承基础映射」。
- 编辑任意方案作用域按键后，顶部方案卡片立即显示该 APP 自己的方案，不再显示原来的方案。
- 方案名称默认「<APP 名> 方案」；不弹出命名对话框，除非用户主动选择显式复制。
- 中文最终字号 ≥12pt；沿用现有卡片栅格，不新增长下拉。

## 旧配置物化与向前兼容

### 没有方案引用的旧 APP

- 适用范围：已有 `buttonBindings`（至少包含一个方案作用域按键）且没有 `mappingProfileID` 的 APP 档案；仅菜单键/TV 键覆盖的 APP 保持默认方案。
- 触发时机：私有组件可用，或宿主侧方案存储已接入时，启动加载完成、清理失效引用之后执行一次。
- 计算方式：按方案作用域的 10 个按键 × 单击/双击/长按，解析 APP 当前最终动作，形成操作表并冻结为方案绑定。
- 去重：只比较「按键 × 手势 → 操作」。方案名、APP 名称、Bundle Identifier、绑定顺序、创建时间、设备身份、快捷键展示文字都不参与；相同操作表只生成或复用一套方案，不同操作表分别生成。
- 同一操作表的多个 APP 共用同一方案；归属登记为该组第一个 APP，其它 APP 只是引用。
- 迁移后 APP 指向该方案，并清空方案作用域逐项覆盖；方案内容就是迁移前那一刻的最终效果。菜单键/TV 键覆盖始终保留。
- 失败边界：方案创建失败或操作表无法形成的 APP 保持原样，不丢失 `buttonBindings`；能力恢复后重试。
- 幂等：已经带 `mappingProfileID` 的 APP 不再迁移；迁移完成再次启动不得新增重复方案。
- 日志只记录迁移 APP 数、方案组数、新建/复用数和结果，不记录 APP、方案名称或 ID。

### 已有方案引用的旧 APP

- 保留原来的 `mappingProfileID` 和方案内容，不重新命名、不重算归属、不按创建历史解释来源。
- 旧宿主方案没有归属台账时，只在该方案的引用 APP 中寻找「默认方案名与方案名一致」的 APP 补归属；共享方案优先登记给名字匹配者，避免把别人正在使用的方案误判给最后使用者。
- 其它归属未知的旧方案保持「归属未知」；第一个修改它的 APP 形成自己的方案，旧方案不被改写。
- 旧 APP 的方案作用域逐项覆盖继续按兼容优先级读取；第一次修改方案作用域按键时，统一冻结进修改者自己的方案并清空。

### 导入、导出与删除

1. 配置导出/导入仍用 `formatVersion = 2`；方案 ID 是本机标识，**不跨机保留**：导出时置空或省略，导入时清空并记录清洗数量。
2. Portable transfer 不扩展对象类型；替换 APP 档案时保留本机菜单键/TV 键覆盖，`mappingProfileID` 一律清空。
3. 删除方案：所有引用它的 APP 回退默认方案，菜单键/TV 键覆盖保留，详情显示「方案已删除，已回到默认方案」；不删除 APP。
4. 删除 APP：只删引用与逐项覆盖；若该 APP 是某方案归属，方案保留并把归属清空，不删除方案内容。
5. 选择「不适用」的方案被拒绝，不写入；若方案在写入后变得不适用（换遥控器/被删），运行期回退默认并提示。
6. 私有方案组件不可用时，APP 页使用宿主侧方案存储：旧配置可物化、选择框可选、修改可自动形成自己的方案；全局方案页的私有组件降级不变。

## 日志与隐私

- 记录：选择方案 / 改回默认 / 修改形成自己的方案 / 原地更新自己的方案 / 运行期命中与回退 / 导入清洗 / 方案删除后的回退。
- 字段只用稳定枚举：`scope=app|global`、`mode=default|assigned`、`owner=self|other|unknown`、`resolution=assigned|fallback_missing|fallback_inapplicable|fallback_locked|fallback_component|fallback_profile_deleted`、`result=success|failed|cancelled`、`count`。
- 不记录 APP 名称、Bundle Identifier、路径、方案名、方案 ID、设备身份、快捷键正文。
- 一次操作只产生一个最终结果；UI 刷新、入队、解码都不算成功。

## 验收

1. A 选 B 方案不修改：A 使用 B，B 修改后 A 跟随；A 自己的旧方案不被改动。
2. A 选 B 方案后修改：A 自动形成自己的方案，B 完全不变；A 的顶部方案卡片立即显示 A 的方案。
3. C 选 A 方案不修改：C 跟随 A；A 修改后 C 跟着变。
4. C 选 A 方案后修改：C 自动形成自己的方案，A 完全不变；之后 A、C 互不影响。
5. 两套方案按键恰好相同但归属不同：运行期互不联动，UI 不显示来源或子母关系。
6. 方案归属未知的旧方案：第一次修改形成修改者自己的方案，旧方案内容不变。
7. 旧 APP 逐项覆盖在升级后形成方案列表：相同操作只出现一套，不同操作分别出现；APP 页面显示对应方案，菜单键/TV 键覆盖保留，二次启动不重复创建。
8. 删除方案后引用它的 APP 回退默认，菜单键/TV 键覆盖保留，可恢复。
9. 未解锁方案不可选、不可读；私有组件与宿主方案均缺失时入口禁用并说明，运行期行为不变。
10. 导入配置不携带方案 ID；导入后 APP 回到默认方案并有一次性说明。
11. 连续快速按、断连、权限撤销、自定义映射关闭、前台切换后无旧 APP 动作或旧方案残留。
12. 中英文、浅色/深色、生产默认与最小窗口下，卡片、选择框与归属状态不裁切、不横向滚动。
13. 真实遥控器、iPhone/网页/Watch 与目标第三方 APP 前台流程分别记录自动化、真实窗口、代理实测和用户实测边界；未完成只能标待验证。

## 明确不做

1. 不按遥控器设备分别保存方案引用。
2. 不建立母方案/子方案、派生关系、来源字段或「基于某方案」的谱系。
3. 不把创建者当作永久归属；归属只随最后一次修改者变化。
4. 不在用户选择方案时自动复制或改写方案。
5. 不给语音键增加方案级动作。
6. 不新增侧边栏一级页面、独立窗口或全局单例导航。
7. 不改变方案页的创建、复制、导入导出、市场与会员流程。
8. 不在公开层重写宏/组合动作执行。

## 落地顺序

1. 归属台账与旧数据兼容：`applicationSchemeOwners`、旧宿主方案归属补登记、旧逐项覆盖冻结。
